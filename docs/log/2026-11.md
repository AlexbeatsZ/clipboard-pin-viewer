### 2026-11-01 fix(publish): 修复单文件发布缺少 WinRT 依赖
- 原因: 现用 0.1.4 目录只剩 apphost EXE 和主 DLL，缺少 Microsoft.Windows.SDK.NET 10.0.19041.38 与 WinRT.Runtime；程序可驻留，但调用剪贴板显示路径时触发依赖加载异常。本机 .NET 10 桌面运行时已正常加载。
- 改动: 版本升级为 0.1.5，在项目文件统一启用 Windows x64、依赖本机运行时的单文件发布；新增不读取剪贴板内容的 --check-dependencies 入口与发布脚本，发布后必须检查单文件产物并实际加载两个 WinRT 程序集；部署到稳定程序目录并更新原有开机启动快捷方式。
- 验证: Release 发布成功，产物只有一个 EXE；发布目录和安装目录的依赖检查均返回成功，Windows SDK 10.0.19041.38、WinRT.Runtime 2.2.0.0，真实 Windows API 返回剪贴板历史已启用；旧进程无可见贴图时正常退出，新进程的真实 F1 消息处理路径成功打开文字窗口，关闭测试窗口后继续驻留；启动快捷方式目标与工作目录回读正确。未修改 ViewerForm，未重复人工拖动、选择和滚轮验收。
- 决策: SDK 10.0.400 不支持框架依赖单文件包的压缩（NETSDK1176），采用未压缩单文件，不改动系统运行时。
